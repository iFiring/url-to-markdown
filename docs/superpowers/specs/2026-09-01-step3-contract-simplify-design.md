# 步骤 3 契约简化设计

- 日期：2026-09-01

## 背景与目标

当前 HEAD 契约是五键容器标记模型（`titleIds`/`descriptionIds`/`standaloneIds`/`listFlowIds`/`listFlowDeleteIds`）：LLM 标记流容器、下游取容器子节点，需要「流 / 游离 / 剔除」三类概念互相配合。工作区草案已改为四键块模型（`titleId`/`descriptionIds`/`paragraphIds`/`dumpIds`），但为解释 paragraphIds 的嵌套多维数组引入了主流/子流、维度=容器链、≥3 块阈值、无主流特例、位置双轨等繁重规则，185 行比 HEAD 版还长。

本设计在草案基础上收敛为：

1. **简化描述**——删除位置双轨、包装层加维、主流特例、data-idx 顺序注记等规则
2. **简化输出结构**——嵌套保留但严格「一流一维」；其余三键为标量/扁平数组
3. **通用性更高**——顶层即文档序序列，主流/游离/standalone 概念全部消解，块清单覆盖更多常见段落级元素

### 非目标（本次不动）

- 步骤 4-9 的脚本与文档（下游仍读旧键，见「兼容性与下游影响」）
- SKILL.md（步骤 3 只引用指南文件、不枚举键名）
- 指南中占位符 token 速览（`{{LONG_TEXT_*}}`/`{{PRE_CODE_TAG|*}}`/`{{TABLE_TAG|*}}`/`{{HIDDEN_TAG|*}}`——读快照的知识，与契约无关，原样保留）
- 单元/集成测试（喂旧键 fixture，不受影响）

## 契约定义

产物 `<url-working-path>/3_key_ids.json`：

```json
{
  "titleId": 2,
  "descriptionIds": [3, 7],
  "paragraphIds": [10, 13, [15, [21, 23, 27, 28], 31, 36]],
  "dumpIds": [9, 19, 37]
}
```

| 键 | 类型 | 语义 |
|---|---|---|
| `titleId` | number \| null | 文章主标题元素 ID，**无论位置**；无主标题或不可判时 `null`。不进 paragraphIds |
| `descriptionIds` | int[] | 元信息块（作者/日期/摘要/副标题/开篇词），**无论位置**。不进 paragraphIds；可为空数组 |
| `paragraphIds` | 嵌套序列 | 整树按**文档序**：标量 = 段落块 ID；数组 = 一个子段落流的块列表。**一流一维**——非流包装层透明、不占维度 |
| `dumpIds` | int[] | **仅段落流之内**、未入选的噪音子块；流外噪音白名单自然裁掉、不标 |

四键互不相交；不选 `<body>`/`<html>`。

## 判定规则

### 段落块（标量）

常见块元素（清单为指引、非白名单）：

- 语义块：`<p>`、`<h1>`-`<h6>`、`<pre>`、`<table>`、`<figure>`、`<ul>`、`<ol>`、`<dl>`、`<blockquote>`、`<button>`、带 `hidden` 属性元素
- 结构块：`<section>`、`<aside>`、`<header>`、`<details>`
- 媒体块：`<img>`、`<picture>`
- 复合 div：图解/图表/卡片/提示框

规则：

- 块 = 完整子树，内部不拆
- 行内元素（`<span>`、`<a>`、`<strong>`、`<b>`、`<em>`、`<i>`、行内 `<code>`、`<br>`、`<hr>`）仅当是段落流的**直接子元素**时可成块
- `<body>`/`<html>` 永不可选

### 段落流（数组）——双条件成流

一个容器是段落流，当且仅当**同时**满足：

1. **规模**：直接子块 ≥3 个（噪音子块不数、子段落流算一个；标题/元信息子块虽不入 paragraphIds，仍是内容、计入）
2. **锚点**：直接子块中至少一个是**锚点块**——`<p>`/`<h1>`-`<h6>`/`<table>`/`<pre>`/`<figure>`/`<ul>`/`<ol>`/`<blockquote>`/`<button>`/`<dl>`/hidden 属性元素，**或其子树内存在按同规则成立的子段落流**

要点：

- **块清单 ≠ 锚点清单**：section/aside/img 等可作块，但不构成锚点证据——否则装满 div 卡片的 `<section>` 会重新通过锚点门
- **锚点清单的判别性质**：锚点标签是**内容语义标签**——标签本身就宣告「我是段落/标题/列表/表格/引用/代码块」，且默认渲染独占一行，是无须看样式即可确认的明显段落块（清洗快照不带样式，成行性只能来自标签语义，判据自洽）。div/section/aside/header 等结构容器标签装什么、占几行由内容与样式决定，所以可作块、不能作锚点。「独占一行」单独不构成判别标准——div/section 默认也是块级渲染。两个务实补充：`<button>` 默认 inline-block，但作为段落流直接子元素时即手风琴/折叠的成行展开钮（行内小按钮不会是流的直接子元素，被作用域天然排除）；hidden 元素不渲染，但 `{{HIDDEN_TAG|n_chars;构成}}` 标明其后是整块折叠正文
- **粒度**：直接子块 <3 个、或无锚点的容器不是流——它整个子树作为上层流的一个块
- **一流一维**：数组与流一一对应；流之间的非流包装层（如剔除噪音后只剩一个子流的中间容器）透明、不占维度
- **主体边界**：判据在文章主体范围内应用；页面级包装不因包含流而成流（其直接子块多为噪音/非内容，自然不满足规模条件）
- **文档序**：paragraphIds 整树按文档序排列；顶层无「主流」特例——顶层就是文档序序列，流子块与流外游离块（流的兄弟、流祖先的兄弟）在顶层同为标量、不做区分（下游迁移效果相同，归属关系可由 DOM `contains()` 重建）

### 语义门与 dumpIds

- 语义噪音：菜单、导航、目录（TOC）、面包屑、页脚链接、相关推荐、评论列表、分享栏、广告、弹窗、表单——**不是文章内容，不进任何键**；嵌在段落流之内的标 `dumpIds`（取流内最高祖先，不列子孙）
- **语义门独立于锚点**：导航/目录内的 `<ul>`/`<p>` 锚点全中，语义上仍是噪音
- 不确定是否噪音的元素不进 dumpIds
- 流外噪音（header/footer/弹窗/侧栏等页面 chrome）无需标记——白名单（title/description/paragraph 三键）之外的元素在步骤 4 自然裁掉

### 校验约束（供下游适配与测试参考）

- 四键互不相交
- 所有 ID 在 DOM 中存在；同一数组的成员互不嵌套且按文档序排列
- 嵌套合法性可由 DOM `contains()` 校验（数组代表的流位于其父数组所对应流的子树内）

## 决策记录

| 决策点 | 结论 | 备选与理由 |
|---|---|---|
| paragraphIds 结构 | 嵌套保留 + 一流一维 | 扁平整数数组曾被推荐（下游零消费者、嵌套信息可由 DOM 重建），用户拍板保留段落流内嵌概念；作为补偿废「包装层加维」规则 |
| 成流锚点 | 锚点块**或**子流（递归） | 仅认直接子块锚点会判死草案主容器 [6]（直接子块全是 div/span/section）；子树任意深度出现锚点标签则卡片内深埋 `<p>` 重新放行卡片阵 |
| 锚点清单 | 11 类 + 子流；块清单扩充项不进锚点 | 防止 section/aside 装载的 div 卡片阵通过锚点门 |
| 锚点判别性质 | 内容语义标签 ∧ 默认独占一行 | 「独占一行」单独不足以区分（div/section 默认也是块级渲染），必须叠加「内容语义标签」；button/hidden 为务实补充（流直接子元素场景） |
| dumpIds 范围 | 只标流内噪音 | 块模型下流内噪音「不列即删」、流外噪音白名单自然裁，全量枚举纯开销 |
| titleId/descriptionIds 口径 | 统一无位置区分 | 位置双轨需要额外规则 + data-idx 顺序注记；两种口径下游迁移效果相同 |
| 块清单扩充 | +section/aside/img/picture（用户提出）；+header/details（对齐草案示例 / hidden 同族折叠块） | img/picture 自行内清单移入块清单 |
| titleId 形态 | 标量（草案现状） | HEAD 为数组；文章主标题天然单数，多 h1 竞争时取文章标题、不可判则 null |
